# Editing an image — a second ComfyUI workflow for Open WebUI

Demo code for module 3 of the "Click by Click" series **Image generation in Open WebUI with
ComfyUI**: the organization's image server can generate; it learns to **edit**. A second ComfyUI
workflow, with a model specialized in editing (FLUX.2 [klein] 4B, Apache 2.0), is connected in the
"Image Edit" section of Open WebUI; the user drops a photo into the chat and describes what to
change.

Video: {{video}}

## Goal

- In ComfyUI, the workflow "Image server — image editing": image loading (node 76), instruction
  (74), loader of the editing model (70), and a **size read on the original image** (99) passed
  through links to the empty image (66) and to the scheduler (62): the result keeps the
  proportions of the photo. Exported in API format (`workflows/image-editing.json`).
- In Open WebUI, the "Image Edit" section: ComfyUI engine, address of the server (editing does not
  reuse the one of generation), workflow, node mapping `image` / 76, **`text`** / 74 (and not
  `prompt`), `unet_name` / 70, width and height empty, editing model.
- In the chat, the built-in tool `edit_image`: the dropped photo is edited, then the image that
  was already edited.

| File | Content |
|---|---|
| `workflows/image-editing.json` | Editing workflow in API format, **as exported in the video** |
| `workflows/image-editing.interface.json` | The same graph in ComfyUI's interface format (19 nodes, original numbers of the Comfy-Org template "FLUX.2 Klein 4B distilled image edit", first subgraph unpacked) |
| `images/mug.png` | The photo of the demo (1216 × 832), generated by the image server of module 1 |
| `open-webui/editing-settings.md` | Every field of the section, the node mapping, what Open WebUI does for each edit |
| `setup_editing.py` | The section set through Open WebUI's API, node mapping check, test, rollback |

The French video shows the same workflow with French node titles (`retouche.json`, prefix
`openwebui/retouche`, photo `tasse.png`); this repository holds its English version, same
structure, same node numbers, prefix `openwebui/edit`.

## Prerequisites

- The image server of modules 1 and 2: ComfyUI v0.41 on a graphics card, connected to Open WebUI
  0.11 (Images page) —
  [`clic-par-clic-comfyui-01-brancher`](https://github.com/guilhem-/clic-par-clic-comfyui-01-brancher),
  [`clic-par-clic-comfyui-02-workflow-organisation`](https://github.com/guilhem-/clic-par-clic-comfyui-02-workflow-organisation).
- In ComfyUI's `models/`: `diffusion_models/flux-2-klein-4b-fp8.safetensors`
  ([black-forest-labs/FLUX.2-klein-4b-fp8](https://huggingface.co/black-forest-labs/FLUX.2-klein-4b-fp8)),
  `vae/flux2-vae.safetensors`, and the text encoder already used for generation,
  `text_encoders/qwen_3_4b_fp8_mixed.safetensors` (the Comfy-Org template expects the 8 GB bf16
  version: the fp8 version is enough). No custom node.
- An 8 GB card is enough: ComfyUI loads the editing model in place of the generation model (about
  25 s to switch, then fifteen seconds or so per edit).
- An Open WebUI **administrator** account; for the users: the "Image Generation" permission and a
  chat model that has this capability (and can call tools).

## Step by step

### 1. The workflow, in ComfyUI

1. Put `images/mug.png` into ComfyUI's `input/` folder (or load it in the "Load Image" node) and
   open `workflows/image-editing.interface.json` (drag and drop it onto the interface) — or
   `python setup_editing.py --comfyui`.
2. Find the numbers (Settings › "Node ID badge mode" › "Show all"): 76 loading, 74 instruction,
   70 loader, 99 size reading.
3. Menu **File › Export (API)**, name `image-editing`.

### 2. The "Image Edit" section, in Open WebUI, by hand as in the video

Admin Panel › Settings › Images, at the bottom: turn **Image Edit** on; engine **ComfyUI**; Base
URL `http://comfyui.comfyui.svc.cluster.local:8188` (verify); "ComfyUI Workflow" › **Upload**
`image-editing.json`; node mapping: Image* `image` / `76`, Prompt* **`text`** / `74`, Model
`unet_name` / `70`, Width and Height empty; Model `flux-2-klein-4b-fp8.safetensors`; size empty;
**Save**. Details: `open-webui/editing-settings.md`.

### 2b. Through the API

```bash
cp .env.example .env                 # OWUI_URL, OWUI_TOKEN (administrator), COMFYUI_URL…
python setup_editing.py --check      # check the workflow and the node mapping
python setup_editing.py              # backs up the current configuration (images-config.backup.json), connects editing
python setup_editing.py --test       # test edit of images/mug.png through Open WebUI
python setup_editing.py --disable    # turns image editing off
python setup_editing.py --restore    # back to the saved configuration
```

The Images page is a setting of **the whole instance**: `images-config.backup.json` keeps the
previous configuration, keys included (file ignored by git, do not share it).

## Try it

With a user account: new chat, "Integrations" menu › "Image", drop `images/mug.png`, then "Put
this mug on a light wooden desk, in the morning light. Keep the logo." Unfold the `edit_image`
call: the instruction written by the chat model and the identifier of the attached image. Go on:
"Now the same scene in winter, with snow outside, behind the window." — the model edits the image
it has just produced.

## Good to know

- **Targeted instructions or whole scenes**: a targeted instruction ("change the color of the logo
  to midnight blue") only touches what is asked. An instruction that changes the scene can
  sometimes change the object itself (handle, logo): "Keep the logo" helps; check the result.
- **Neither steps nor seed** for editing in Open WebUI: they are set in the workflow.
- **Two images to combine**: two load nodes, and two numbers on the "Image*" row (one image per
  number, in order).
- **Two models for one card**: ComfyUI loads one, then the other; the first edit after a
  generation waits for the editing model to load. Measurements and queue: module 7.
- **Cleanup**: the images sent by Open WebUI stay in ComfyUI's `input/` (names `<uuid>.png`), the
  results in `output/openwebui/` (prefix `openwebui/edit`); Open WebUI keeps its own copy of each
  image.
